# VPS Control Room — Full Audit (2026-06-11)

A cross-cutting audit of the whole project: bugs, issues, and improvement ideas
from **every angle** — end user, UI/UX, developer/code-quality, security,
build/deploy/ops, cross-platform/native-feel, and documentation.

> **Method.** Findings were gathered by reading the code directly. Every item
> tagged **✅ verified** was confirmed at the cited `file:line` during this audit.
> Items tagged **🔎 scan** were surfaced by a sweep and are very likely real but
> were not line-by-line re-confirmed — treat them as leads, confirm before fixing.
> Severity = blast radius if left alone, not difficulty to fix.

> **✅ Resolved in the 2026-06-11 pass** (build-verified, agent + frontend):
> doc truth (24→16 + Next 15) · agent `exit(1)` on **uncaught exception** (an
> unhandled *rejection* stays log-only — safer for a long-running service) +
> systemd `StartLimit` · pty env secret-scrub · Windows launcher host/port +
> quote-strip ·
> PWA real screenshots + `launch_handler` + `mobile-web-app-capable` ·
> reduced-motion media query · **native shell Phase 0** (`shared/platform/`:
> detect, provider, tokens, theme switch, bridges) · **pane error boundary**
> (a crashed pane now offers "Reload pane" instead of vanishing) ·
> service-worker `controllerchange` listener cleanup · version-guard **cross-tab
> dismissal** (per-build-id, `storage`-synced). Remaining 🔎 items below are
> still open.
>
> **Re-checked & dropped:** the `deploy.sh` flock "stale lock" concern (§5) is a
> non-issue — `flock` on an fd auto-releases when the process dies, and the
> `/tmp` lock file lingering is harmless; no trap needed.

**Scope checked:** `frontend/` (74 ts/tsx), `agent/src/`, `scripts/` (local +
win-local + deploy), `install.*`, `.github/workflows/`, config files, and all of
`docs/` + root markdown.

## 4. Security perspective

Fundamentals are good: HMAC-SHA256 signed cookies, timing-safe compare, device
approval as a real second factor, login rate-limiting with a global backstop,
agent health server bound to loopback by default. Concerns:

| Sev | Where | Issue | Fix |
|-----|-------|-------|-----|
| Med | `agent/src/terminal/profiles.ts:191-196` | Every pty is spawned with `...process.env`, so the child shell inherits `CONTROL_ROOM_SECRET`, `CONTROL_ROOM_SESSION_SECRET`, `AGENT_GATEWAY_SECRET`. Any command/agent in a pane can `echo $CONTROL_ROOM_SECRET`. | Build an allowlisted env (`PATH`, `HOME`, `TERM`, `COLORTERM`, locale, `CONTROL_ROOM_*` *labels* only) + the user `envBlock`; never spread the master secrets. ✅ |
| Med | `frontend/app/api/auth/login/route.ts` (`CONTROL_ROOM_LOCAL_TRUST`) | Local auto-approve flag is safe by intent, but a copied `.env.local` to a VPS silently disables the second factor. | Hard-fail at startup if `LOCAL_TRUST` is set while `NODE_ENV=production` (or when bind host ≠ loopback). 🔎 |
| Med | Login rate-limit map | Spoofed `X-Forwarded-For` churns the per-IP map up to its cap. | Use an LRU/timestamp queue; trust only the first proxy hop. 🔎 |
| Low | `agent/src/terminal/gateway/http.ts` upload | TOCTOU between `fs.access` collision check and rename. | `fs.open(..., 'wx')` and retry on `EEXIST`. 🔎 |
| Low | `.env.local:5` (local dev) | Login secret is the weak `namam787898`. Fine locally (device approval is the real factor) — **must not** ship to any network deploy. | Production secret = `openssl rand -hex 32`; keep the weak one local-only. ✅ (do not print value) |
| Info | `agent/src/app/health-server.ts` | No HSTS, but it's loopback-bound so N/A — unless `AGENT_HEALTH_HOST` is changed to `0.0.0.0`. | If host ≠ loopback, refuse to start or add TLS+HSTS. 🔎 |

## 5. Build / deploy / ops perspective

| Sev | Where | Issue | Fix |
|-----|-------|-------|-----|
| High | `scripts/win-local/start-frontend.ps1:16` | Hardcoded `--hostname 127.0.0.1`, no `--port`; ignores `CONTROL_ROOM_HOST/PORT`. Diverges from the Linux brain which honors env. | Read `$env:CONTROL_ROOM_HOST` / `CONTROL_ROOM_PORT` with 127.0.0.1/4000 defaults. ✅ |
| High | `scripts/win-local/start-agent.ps1` | Env parser doesn't strip surrounding quotes (the Node brain at `control.mjs` does). Quoted value → wrong secret. | Strip matching leading/trailing quotes after the first `=`. ✅ |
| Med | `scripts/deploy.sh:17-18` | `flock` lock has no `trap … EXIT` cleanup; a SIGKILL leaves a stale lock blocking future deploys. | `trap 'flock -u 9; rm -f "$LOCK_FILE"' EXIT` after acquiring. 🔎 |
| Med | `scripts/deploy.sh:93-123` `activate_frontend_build` | Stops service then `mv`s dirs; a mid-swap failure (disk full) can leave no `.next`. Rollback assumes `.next-previous` exists. | Symlink-swap (`ln -sfn`) the live dir — atomic on POSIX — instead of stop+mv. 🔎 |
| Med | `scripts/deploy.sh:156-160` | `git pull --ff-only` fails confusingly on a shallow clone. | Detect `.git/shallow` → `git fetch --unshallow` first. 🔎 |
| Low | `.github/workflows/deploy.yml` | Reads env from a host path with no mode/permission check. | Assert `.env.local` is mode `600` before use. 🔎 |
| Low | systemd agent unit (`scripts/install-systemd.sh`) | `Restart=always` + `RestartSec=5`, no `StartLimit*` → tight crash-loop possible. | Add `StartLimitBurst=3`, `StartLimitIntervalSec=60`. 🔎 |
| Low | `scripts/cleanup-terminal-runtime.sh` | Hardcoded `${HOME:-/home/rahman}` leaks the author's username and misleads on other hosts. | Use `${HOME}` only; error if unset. 🔎 |
| Note | `frontend/package-lock.json` is **gitignored**; deploy uses `npm install` | Reproducibility gap: VPS resolves fresh versions each deploy. Intentional today, but worth a conscious decision. | Either commit the lockfile + `npm ci`, or document why floating is acceptable. ✅ |
